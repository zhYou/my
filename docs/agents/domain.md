# 领域文档

本文件规定工程技能如何读取和消费本仓库的领域文档。

## 探索前读取

- 根目录 `GLOSSARY.md`。
- `docs/adr/` 中与改动区域有关的 ADR。

本仓库采用 single-context 布局。文件不存在时继续探索，不报告缺失；只有在实际形成领域术语或
架构决策时，才由 `domain-modeling` 惰性创建对应文件。

## 布局

```text
/
├── GLOSSARY.md
├── docs/
│   └── adr/
│       └── 0001-example-decision.md
└── ...
```

`GLOSSARY.md` 是领域术语的单一事实来源；ADR 记录难以逆转的重大决策。修改或提议相关领域概念时，
先检查已有定义和 ADR。

## 使用术语

在 issue 标题、重构建议、假设和测试名称中引用 `GLOSSARY.md` 的术语，不自行改用其中明确排除的
同义词。

需要使用的概念尚未收录时，先判断它是项目真实缺失的语言，还是新造且不必要的术语；需要沉淀时
交给 `domain-modeling`。

## ADR 冲突

输出与已有 ADR 冲突时，必须明确指出，不得静默覆盖：

> 与 ADR-0007 冲突，但由于……值得重新讨论。
